## Replace OpenAI with Gemini

We are switching the AI Software Employee from OpenAI to Google's Gemini API.

IMPORTANT:
- Do NOT rebuild the application.
- Preserve the existing FastAPI architecture.
- Preserve GET /.
- Preserve POST /chat.
- Preserve the existing filesystem tools:
  - list_files
  - read_file
- Preserve the existing tool registry.
- Preserve all filesystem security protections.
- Do NOT implement write_file yet.
- Do NOT add terminal execution.
- Do NOT add Docker.
- Do NOT add GitHub.
- Do NOT add database.
- Do NOT add frontend.
- Do NOT add autonomous behavior.

The only goal of this task is to replace the OpenAI LLM integration with Gemini.

==================================================
1. REMOVE OPENAI DEPENDENCY
==================================================

Remove the OpenAI Python SDK from requirements.txt.

Remove python code that imports:

openai

Do not leave unused OpenAI integration code behind.

==================================================
2. ADD GEMINI SDK
==================================================

Add the official Google Gemini Python SDK:

google-genai

Keep python-dotenv if it is still required by the project.

==================================================
3. ENVIRONMENT VARIABLE
==================================================

The application must read:

GEMINI_API_KEY

from the environment.

Never hard-code the API key.

Never return the API key in an API response.

Never log the API key.

Update .env.example so it contains:

GEMINI_API_KEY=

Do not put a real API key in .env.example.

==================================================
4. UPDATE app/llm.py
==================================================

Replace the OpenAI implementation with the official Google GenAI Python SDK.

Use:

from google import genai

Create the Gemini client using the GEMINI_API_KEY environment variable.

Use this stable model initially:

gemini-2.5-flash

Keep the model name in one configuration constant/environment variable so it can easily be changed later.

For example:

GEMINI_MODEL=gemini-2.5-flash

If GEMINI_MODEL is not configured, default to:

gemini-2.5-flash

==================================================
5. PRESERVE FUNCTION CALLING
==================================================

The existing filesystem tools must continue to work through Gemini function calling.

The model must be able to call:

list_files

read_file

The application should:

1. Send the user's request to Gemini with the available tools.
2. Detect function calls requested by Gemini.
3. Execute the corresponding local filesystem tool.
4. Send the tool result back to Gemini.
5. Allow Gemini to continue.
6. Return the final natural-language response.

Keep the tool-call loop bounded.

Use a maximum of 5 tool-calling rounds.

Never create an infinite loop.

Preserve the existing tool behavior.

Do not weaken any filesystem security checks.

Gemini must only receive tools that are explicitly registered.

Currently the available tools are:

read_file

No shell commands.

No Python execution.

No arbitrary code execution.
